Getting started

Bring up concierge-service and/or cook-service locally, backed by real credentials for whichever channel and AI provider you're integrating.

Requirements

  • Node.js ≥ 20
  • pnpm (this is a pnpm workspace monorepo)
  • Docker, if you want Redis/Postgres/services running together via Compose
  • Credentials for whichever pieces you're wiring up: OpenAI or Google (Gemini), Google Calendar, and at least one of WhatsApp Cloud API / Telegram Bot API / Twilio

Install

pnpm install

Configure environment variables

Each service reads its config from environment variables, validated at startup with Zod — a missing or malformed value fails immediately with a clear message rather than surfacing confusingly later. Copy the example file for each service you're running and fill it in:

cp apps/concierge-service/.env.example apps/concierge-service/.env
cp apps/cook-service/.env.example apps/cook-service/.env

cook-service only queries the Pinecone index — it doesn't populate it. Run pnpm --filter @gracesoft-sentinel/provider-recipe-pinecone run sync first (its own env: GOOGLE_SERVICE_ACCOUNT_EMAIL/PRIVATE_KEY, GOOGLE_DRIVE_RECIPES_FOLDER_ID, OPENAI_API_KEY, plus the three Pinecone vars above) to (re)index a Drive folder of personal recipes.

Run a service

pnpm --filter @gracesoft-sentinel/concierge-service build
pnpm --filter @gracesoft-sentinel/concierge-service start

Or bring up Redis, Postgres, and both services together:

docker compose up --build

Verify it's alive

curl http://localhost:3000/health
curl http://localhost:3000/ready

/health always returns 200 once the process is up. /ready actually pings Redis and Postgres and returns 503 if either is unreachable — point your orchestrator's readiness probe at this one, not /health.
